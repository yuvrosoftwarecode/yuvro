✅\n**Chosen:** Single Helm chart for all services  \n**Rationale:**\n- Reduces configuration duplication\n- Ensures environment parity\n- Simplifies maintenance\n- Single source of truth\n\n### Decision 2: Single Namespace ✅\n**Chosen:** All services in `yuvro` namespace  \n**Rationale:**\n- Simplified service discovery\n- Better for development workflow\n- Reduced operational complexity\n- Easier network policies\n\n### Decision 3: GitHub Container Registry ✅\n**Chosen:** GHCR for image storage  \n**Rationale:**\n- GitHub-native integration\n- No separate AWS infrastructure\n- Simpler authentication flow\n- Reduced operational burden\n\n### Decision 4: LoadBalancer Services ✅\n**Chosen:** Kubernetes LoadBalancer for local  \n**Rationale:**\n- Same ports as Docker Compose\n- No manual port management\n- Better developer experience\n- Docker Desktop native support\n\n### Decision 5: ConfigMap for Configuration ✅\n**Chosen:** Kubernetes ConfigMap for environment variables  \n**Rationale:**\n- Native Kubernetes solution\n- Easy to manage\n- Works with secrets for sensitive data\n- Supports hot reload\n\n---\n\n## Comparison: Before vs After\n\n### Before Refactoring\n- ❌
